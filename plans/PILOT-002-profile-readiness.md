## Intended bounded change

1. In `useProductReadiness`, evaluate the existing six-point readiness predicate using the required `meResponse.data.languageProfiles` snapshot. Do not call `listMyLanguageProfiles()` for this boundary check. Keep all current actor, profile ID, IANA timezone, active `vi`→`en` status, canonical goal, and integer daily-minutes checks. Missing or invalid profile data must fail closed as not-ready/error; it must never make a route ready by bypassing the predicate.
2. Add a 45-second deadline for one entire readiness operation, measured from its start and including token acquisition, fetch, and response-body reading. This keeps the owner-reported usual ~30-second wait below the automatic timeout; it is a bounded recovery limit, not a promised performance improvement. On expiry, leave the route protected, show the existing safe error/retry state with an actionable timeout message, and wait for the learner to press the existing retry control. Do not add automatic retries or a readiness cache.
3. Use an optional `AbortSignal` only through the internal `getMe` read path and its `HttpApiClient` request. The operation deadline can stop waiting even if token acquisition is pending; after token acquisition, an already-aborted read must not start a fetch. If fetch/body reading has begun, abort it where supported. Do not add timeout, cancellation, or retry policy to writes or unrelated API methods.
4. Give each readiness check an operation generation. Abort/supersede the prior check on manual retry, actor change, logout, disabling readiness, or unmount. A late result from an obsolete operation must not update readiness state. In `HttpApiClient`, an aborted or superseded `/v1/me` response must not update the shared `me` ETag, including when the actor is unchanged and a newer same-actor refetch has already completed.
5. Preserve current initial session loading, disabled-route behavior, onboarding flow, Today flow, API wire contract, backend semantics, and domain readiness rules. Do not change the `MeProfile` schema, database, hosted actors/state, K2 evidence, or hosting configuration. A warm `/health` response is not profile-read latency evidence; free-tier idle spin-up remains only a possible separate delay.
